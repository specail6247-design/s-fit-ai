## 2025-06-19 - [NEXT_PUBLIC_ API Key Exposure]
**Vulnerability:** A hardcoded `NEXT_PUBLIC_OPENAI_API_KEY` environment variable reference was found in client-side code (`lib/visionService.ts`), initialized directly in the OpenAI SDK client.
**Learning:** In Next.js, any environment variable prefixed with `NEXT_PUBLIC_` is automatically bundled and sent to the client browser in plain text. This is extremely dangerous for sensitive keys like OpenAI or database credentials, as anyone can extract them and incur charges or access private systems. The use of `dangerouslyAllowBrowser: true` compounded the risk by enabling the SDK to run on the frontend.
**Prevention:** Never use the `NEXT_PUBLIC_` prefix for secrets. Sensitive API interactions (like calling OpenAI) must be isolated within server-side API routes (e.g., `app/api/...`) where the standard `process.env.OPENAI_API_KEY` (without the prefix) is securely accessed on the server. If a client-side mock is needed for a demo, use a definitive hardcoded mock string (e.g., `'mock-key'`) instead of falling back to environment variables.
