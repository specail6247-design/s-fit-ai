## 2026-03-02 - [CRITICAL] Prevented SSRF and Path Traversal in Virtual Try-On API
**Vulnerability:** The `app/api/try-on/route.ts` endpoint directly concatenated user paths without validation (`path.join(process.cwd(), 'public', relativePath)`) and used blocking synchronous I/O (`fs.readFileSync`). Additionally, it allowed arbitrary protocol inputs for external garment images (allowing any scheme Replicate or Next.js could fetch).
**Learning:** Unrestricted image/URL fetches in Next.js Serverless/Node environments allow attackers to perform SSRF or execute path traversal attacks to read internal local application files outside `public/` via the `localFileToDataUri` function. Sync file operations can easily block event loops.
**Prevention:** Use `path.resolve()` to get the absolute path, and strictly verify it starts with the expected base directory (`absolutePath.startsWith(publicDir + path.sep)`). Validate all user-supplied image URLs using strict protocol allowlists (e.g., `http://`, `https://`, `data:image/`). Always use `fs.promises` (async operations) for Node.js filesystem interaction.
