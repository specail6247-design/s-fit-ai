## 2024-05-20 - Path Traversal & Blocking I/O in API Routes
**Vulnerability:** The API route `app/api/try-on/route.ts` processed local paths provided by users via `path.join(process.cwd(), 'public', relativePath)` without checking if the resulting path escaped the `public` directory. Additionally, the route used synchronous file reading methods like `fs.readFileSync` and `fs.existsSync`, which block the entire Node.js event loop on the main thread.
**Learning:** `path.join` resolves relative paths like `../` within its arguments, so a user providing `../../../etc/passwd` could escape the intended base directory. Synchronous I/O in Next.js API routes (which run on a Node.js runtime) can degrade performance and cause denial-of-service (DoS) under load, as the single thread is blocked from serving other requests until the file operation completes.
**Prevention:** Always use `path.resolve` to determine the absolute target directory and the final requested path. After resolving, verify that the final path strictly starts with the base directory plus a path separator (`baseDir + path.sep`) or is exactly the base directory. Always use the asynchronous `fs.promises` API (e.g., `fs.promises.readFile`, `fs.promises.access`) for file I/O operations in Node.js backends.
